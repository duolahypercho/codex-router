- **Ambient Desktop app state no longer fails a routed turn before the provider sees it.** Codex Desktop persists unpaired `function_call_output` items for app context: older builds use namespace `codex_app`, and current builds use `agent` for the open page, the selected page, and in-app browser tabs. Those items have a name and an item id, but no `call_id`. Recovery used to accept only `codex_app`, so each new `agent` name reached the Responses adapter, which rejects a tool result that cannot be paired, and the caller saw HTTP 400 `The API-provider forwarder could not complete the request.` Both namespaces are now rewritten into readable history. A result that already has a `call_id` stays paired, and a malformed result in any other namespace still fails closed.
