- **Desktop page context no longer fails a routed turn before the provider sees it.** Codex Desktop injects the open page and the selected page as `function_call_output` items in the `agent` namespace (`codex_apps_open_page`, `codex_apps_selected_page`, including `_part_<n>_of_<m>`) with an item id and no `call_id`. Orphan app recovery only accepted `namespace === "codex_app"`, so these items reached the Responses adapter, which rejects a tool result that cannot be paired, and the caller saw HTTP 400 `The API-provider forwarder could not complete the request.` Those page results are now rewritten into readable history, the same way unpaired `codex_app` results already were. A page result that already has a `call_id` stays a tool result, and every other malformed tool item still fails closed.
